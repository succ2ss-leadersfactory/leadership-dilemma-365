# 과정개발 에이전트 v1.0 · 배포 안내

방법론 문서를 기준으로 1~3단계(요구 분석 → 고객 확인 요청 → 유형·무대 제안 → 커리큘럼표)를 진행하는 웹앱입니다. Cloudflare Worker 한 개가 웹앱 화면과 Anthropic API 연결을 함께 맡습니다. API 키는 Worker 안에만 있고 브라우저로 나가지 않습니다.

## 1. 준비 (처음 한 번)

1. **Anthropic Console**에서 이 용도의 워크스페이스를 따로 만들고, 그 워크스페이스의 API 키를 발급합니다. 같은 워크스페이스에 월 비용 상한을 걸어 둡니다.
2. **Cloudflare** 대시보드 → Workers & Pages → Create → Worker를 만듭니다(이름 예: `course-agent`).
3. **Edit code**에서 기본 코드를 모두 지우고 `dist/course-agent-worker.js` 내용을 통째로 붙여 넣은 뒤 Deploy합니다.
4. Worker → **Settings → Variables and Secrets**에 아래를 넣습니다.

| 이름 | 종류 | 값 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | Secret | Console에서 받은 API 키 |
| `ACCESS_CODE` | Secret | 웹앱 접속 코드. 16자 이상, 헷갈리는 글자(0·O·1·l·I) 없이 |
| `MODEL` | Text (선택) | 기본 `claude-sonnet-5-5`. 더 깊게 쓰려면 `claude-opus-5-5` |
| `MAX_TOKENS` | Text (선택) | 한 번 응답 최대 길이. 기본 12000, 상한 32000 |

5. `https://course-agent.<내 계정>.workers.dev/` 를 열고 접속 코드를 넣습니다. 오른쪽 위에 모델 이름이 초록 점과 함께 보이면 연결된 것입니다. 주소 뒤에 `?code=접속코드`를 붙여 보내면 코드 입력 없이 들어갑니다(받은 사람 브라우저에 저장됨).

## 2. 쓰는 법

- 단계마다 **생성 → 읽기 → 수정 요청 또는 직접 고치기 → 승인** 순서입니다. 승인해야 다음 단계가 열립니다.
- **수정 요청**은 에이전트가 산출물 전체를 다시 쓰고 끝에 "이번 수정에서 바뀐 것"을 붙입니다.
- **직접 고치기**로 고친 내용이 다음 단계로 넘어갑니다.
- 앞 단계를 고치면 뒤 단계에 "앞 단계 바뀜" 표시가 붙고 승인이 풀립니다.
- 2단계는 회신 칸이 비어 있으면 **확인 요청서**를, 고객 회신을 붙여 넣고 다시 생성하면 **회신 반영 결과**를 만듭니다.
- 3-1단계는 순위 없이 2~3안을 내고, 3-2단계에서 설계자가 고른 안과 바꿀 점을 적어야 생성됩니다.
- 작업 내용은 그 브라우저에만 저장됩니다. **백업**(JSON)으로 받아 두고, 다른 컴퓨터에서는 **복원**합니다. **내보내기**는 모든 단계를 마크다운 한 파일로 받습니다.
- **설정**에서 방법론 문서를 이 브라우저에 한해 고칠 수 있습니다. 모두에게 적용하려면 `src/knowledge.md`를 고치고 다시 빌드합니다.

## 3. 고치고 다시 배포하기

```
src/knowledge.md        방법론 문서(에이전트 지식)
src/stages.js           에이전트 역할과 단계별 지시문
src/app.html            웹앱 화면
src/worker.template.js  연결 서버
build.mjs               빌드 → dist/course-agent-worker.js
test/serve.mjs, e2e.py  모의 API로 로컬 점검
```

`node build.mjs` 후 새 `dist/course-agent-worker.js`를 Worker에 다시 붙여 넣고 Deploy합니다. 변수와 비밀은 그대로 남습니다.

## 4. 비용과 보안

- 방법론 문서는 요청마다 시스템 프롬프트로 함께 가며, 프롬프트 캐시를 켜 두었습니다. 화면 아래 토큰 줄에 "캐시"가 보이면 반복 비용이 줄어든 것입니다.
- 모델과 최대 길이는 Worker가 정합니다. 화면에서 바꿀 수 없습니다.
- 고객 자료를 붙여 넣을 때 개인정보와 대외비는 빼고 넣습니다. 고객사 AI 정책상 외부 API 전송이 괜찮은지 먼저 확인합니다.
- 접속 코드가 퍼졌다면 `ACCESS_CODE`만 바꾸면 됩니다.

## 5. 문제 해결

| 화면 메시지 | 할 일 |
| --- | --- |
| 접속 코드가 맞지 않습니다 | Worker의 `ACCESS_CODE`와 같은지 확인 |
| 연결 서버에 ANTHROPIC_API_KEY가 없습니다 | 변수와 비밀에 Secret으로 넣고 다시 Deploy |
| API 키가 올바르지 않습니다 | Console에서 키 상태 확인, 새 키로 교체 |
| 모델을 찾지 못했습니다 | `MODEL` 값 철자 확인 또는 비워 두기 |
| 사용 한도에 닿았습니다 / 크레딧이 부족합니다 | Console의 Limits·Billing 확인 |
| 응답이 최대 길이에 닿아 끝부분이 잘렸습니다 | `MAX_TOKENS`를 16000~24000으로 올리기 |
