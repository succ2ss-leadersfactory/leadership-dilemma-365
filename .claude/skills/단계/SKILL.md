# /단계

받은 값: `$ARGUMENTS` (첫 낱말이 단계, 나머지가 메모)

## 1. 승인 확인 (건너뛰지 않는다)

```
python3 tools/status.py check $0
```

- 첫 줄이 **멈춤**이면 서브에이전트를 부르지 않는다. 출력된 이유를 그대로 보여 주고, 무엇을 하면 되는지(예: `/승인 1`, `00_요청.md` 채우기, `/수정 2 ...`) 한 줄로 알린 뒤 끝낸다. 설계자가 대신 진행하라고 해도 승인 기록 없이 넘어가지 않는다.
- 첫 줄이 **진행**이면 출력의 과정 폴더, 방식, 읽을 파일, 쓸 파일을 기억한다.

## 2. 단계별 준비

- **3-1**: 메모가 있으면 과정 폴더의 `03a_설계자방향.md`에 메모를 그대로 적는다(이미 있으면 덮어쓰기 전에 묻는다). 읽을 파일에 추가한다.
- **3-2**: 메모가 설계자 선택이다(예: "안 B. 시작 13:00, 휴식 10분 두 번, 오프닝 줄이기"). 메모가 없고 `04a_설계자선택.md`도 없으면 멈추고 "어느 안으로 갈지, 바꿀 점, 시작 시각·휴식(있으면)을 `/단계 3-2 안 B ...`처럼 붙여 주세요"라고 묻는다. 메모가 있으면 아래 모양으로 `04a_설계자선택.md`에 적는다(이미 있으면 덮어쓰기 전에 묻는다). 설계자가 쓴 말만 옮기고 해석을 덧붙이지 않는다.

  ```
  # 04a 설계자 선택

  ## 설계자 선택
  (메모 중 고른 안과 바꿀 점)

  ## 시간 조건
  시작 시각: (메모에 있으면, 없으면 "없음")
  휴식: (메모에 있으면, 없으면 "없음")
  ```

## 3. 서브에이전트 부르기

Agent 도구로 아래 서브에이전트를 부른다. 반드시 `run_in_background: false`로 불러 결과가 올 때까지 기다린다(백그라운드로 돌리면 이 명령의 도구 허용이 끝난 뒤 결과가 와서 검산·기록을 못 한다).

| 단계 | subagent_type |
| --- | --- |
| 1 | needs-analyst |
| 2 | client-liaison |
| 3-1 | structure-designer |
| 3-2 | structure-designer |

넘길 내용(그대로 채워서):

```
과정 폴더: <check 출력의 과정 폴더>
단계: <단계와 이름>
방식: <생성 또는 회신반영>
읽을 파일: <목록, 과정 폴더 기준>
쓸 파일: <파일 이름>
knowledge/methodology.md와 knowledge/stage-instructions.md의 AGENT_ROLE과 이 단계 부분을 끝까지 읽고 그대로 따르세요.
쓸 파일 하나만 만들고 status.md는 건드리지 마세요.
```

## 4. 결과 확인과 기록

서브에이전트가 그래도 백그라운드로 넘어가 결과가 나중에 오면, 결과 알림을 받은 그때 아래를 끝까지 한다. 기록을 빠뜨린 채 다른 일을 하지 않는다.


1. 쓸 파일이 실제로 생겼는지, 끝에 `## 넣은 가정`과 `## 설계자 확인 필요`가 있는지 확인한다. 없으면 서브에이전트에 한 번 더 고치게 한다.
2. 3-2이면 `python3 tools/check_time.py <과정 폴더>/04_커리큘럼표.md`를 직접 한 번 더 돌려, 파일의 `## 시간 검산`이 이 결과와 같은지 본다. 다르면 서브에이전트에 고치게 한다.
3. 기록한다(승인이 아니라 초안 기록이다).

   ```
   python3 tools/status.py mark $0 <방식> "<쓸 파일 이름>"
   ```

## 5. 설계자에게 답하기

인사 없이 아래만.

- 만든 파일 경로
- 서브에이전트가 돌려준 요약(3-1이면 안별 한 줄, 3-2이면 검산 결과 마지막 줄과 강의:실습 비율)
- "설계자 확인 필요" 항목 그대로
- 다음 할 일: 읽어 보고 `/검토 $0`, `/수정 $0 <요청>`, 또는 채팅에서 `/승인 $0`

승인은 기록하지 않는다. 다음 단계를 이어서 시작하지 않는다. 4번의 기록(`status.py mark`)을 마치기 전에는 답을 끝내지 않는다.
