# /수정

받은 값: `$ARGUMENTS` (첫 낱말이 단계, 나머지 전부가 수정 요청)

단계 값: 1, 2(확인 요청서), 2b(회신 반영), 3-1, 3-2

## 1. 확인

- 수정 요청이 비어 있으면 멈추고 무엇을 바꿀지 묻는다.
- 대상 파일: 1 → `01_과정브리프.md`, 2 → `02_확인요청서.md`, 2b → `02b_회신반영.md`, 3-1 → `03_구조안.md`, 3-2 → `04_커리큘럼표.md`
- `python3 tools/status.py current`로 과정 폴더를 확인하고, 대상 파일이 없으면 멈추고 `/단계`로 먼저 만들라고 알린다.

## 2. 이전 판 보관

```
python3 tools/status.py archive $0
```

출력된 보관 경로(`_v1`, `_v2` ...)를 기억한다. 보관이 실패하면 다시 쓰지 않고 멈춘다.

## 3. 서브에이전트로 다시 쓰기

단계에 맞는 서브에이전트(1 → needs-analyst, 2·2b → client-liaison, 3-1·3-2 → structure-designer)를 Agent 도구로 `run_in_background: false`로 불러(결과가 올 때까지 기다림) 아래를 넘긴다.

```
과정 폴더: <폴더>
단계: <단계>
방식: 수정
대상 파일: <대상 파일>  (이 파일을 처음부터 다시 써서 같은 이름으로 저장)
읽을 파일: 대상 파일, 그리고 이 단계를 처음 만들 때 읽은 입력 파일 전부(CLAUDE.md "입력 이름과 파일" 표 기준)
<수정 요청>
(설계자가 쓴 수정 요청을 한 글자도 바꾸지 않고)
</수정 요청>
knowledge/stage-instructions.md의 "수정 지시 (REVISE_INSTRUCTION)"를 그대로 따르세요. 요청과 상관없는 부분은 그대로 두고, 맨 끝 "## 설계자 확인 필요" 뒤에 "## 이번 수정에서 바뀐 것"(3줄 이내)을 붙이세요.
3-2이면 tools/check_time.py를 다시 돌려 "## 시간 검산"을 새 결과로 바꾸세요.
```

## 4. 확인과 기록

1. 대상 파일 끝에 `## 이번 수정에서 바뀐 것`이 있는지 확인한다. 없으면 서브에이전트에 고치게 한다.
2. 3-2이면 `python3 tools/check_time.py <폴더>/04_커리큘럼표.md`를 직접 돌려 파일의 검산과 같은지 본다.
3. 기록한다. 이 명령이 이 단계의 승인을 풀고, 뒤 단계에 "앞 단계 바뀜"을 표시한다.

   ```
   python3 tools/status.py mark $0 수정 "<수정 요청을 한 줄로 줄인 말> · 이전 판 <보관 파일 이름>"
   ```

## 5. 답하기

- 고친 파일과 보관한 이전 판 경로
- "이번 수정에서 바뀐 것" 그대로
- status.py 출력에 "승인 풀림"이나 "앞 단계 바뀜"이 있으면 그대로 알리고, 뒤 단계는 다시 확인해 `/수정`하거나 `/승인`해야 한다고 알린다.
